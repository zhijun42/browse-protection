# Morning Protection

在设定的时段屏蔽指定网站，并分别计算学习和娱乐时间。默认：**22:00 – 10:30 屏蔽 xiaohongshu.com、amap.com、douban.com；小红书每天有 40 分钟基础娱乐额度**。

## 安装

1. Chrome 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择这个目录 `morning-protection`
4. 工具栏弹窗的「设置」（或扩展详情页 →「扩展程序选项」）里可以改时段和网站

## 学习与娱乐

- 在工具栏弹窗选择网站，点「开启学习」并输入分钟数。浮窗显示已用与计划时间；「延长学习」增加本次计划，不清零已用时间。
- 只有网站处于当前 Chrome 前台标签时才计时。同一标签打开图文、视频或返回列表会继续计时；切去别处查资料、离开 Chrome、锁屏或休眠会暂停。同站多个标签和子域共用额度。
- 可直接拖动计时浮窗，位置会保存在本机。
- 学习到点会停在提示页。可「延长学习」回原页面，也可「完成学习」切回当天剩余的娱乐额度。等你选择时两边都不计时。
- 娱乐额度用完会显示当天累计时间，可「结束浏览」关闭当前标签，或「再看 10 分钟」「再看 20 分钟」。每轮续时用完都会再次停下来；续时不清零累计时间。娱乐到点后也可以从工具栏弹窗开启独立学习。
- 按设备本地日期在午夜重置娱乐用时和续时，未完成的学习继续保留。时长只记录在本机。可在设置的「每日娱乐额度」加入 `youtube.com 40` 等规则，每站独立计时。
- 定时屏蔽优先，期间不能用学习或续时解锁。到了解锁时间，只有当前额度也允许的标签才自动返回原页面。

## 工作方式

- `background.js` 在屏蔽开始和结束时间设置 alarm，并保留每分钟检查作为兜底
- 定时屏蔽、学习到点和娱乐到点使用同一套 `declarativeNetRequest` 动态规则，符合任一屏蔽条件就重定向到 `blocked.html`
- 同时扫一遍已打开的标签页，命中的直接跳到提示页——否则时段一开始，已经打开的页面还能继续刷
- 结束时先更新屏蔽规则，再自动恢复符合条件、仍停在屏蔽页的标签：已打开的网页优先使用浏览器后退；时段内新访问的网址直接重新打开
- 原网址保存在屏蔽页的地址片段中，关闭再恢复浏览器、复制标签页后仍可恢复；旧版本已经打开的屏蔽页通过浏览器后退恢复
- 电脑休眠错过结束时间时，在唤醒后补做；浏览器启动、扩展重新加载或关闭屏蔽后也会检查并恢复
- 已经关闭或自行切换到其他页面的标签不会被恢复操作改变
- 屏蔽时段跨午夜，判断条件是 `cur >= 22:00 || cur < 10:30`

## 更新与验证

1. 修改文件后，在 `chrome://extensions/` 找到 Morning Protection，点击重新加载
2. 将屏蔽结束时间临时设为接下来的一分钟，确认多个屏蔽页会自动恢复；测完恢复原设置
3. 回归测试：使用 Node.js 22 或更新版本，在项目目录运行 `node --test tests/*.test.mjs`

## 已知的边界

- 这是「减速带」不是「锁」：`chrome://extensions/` 里两秒就能关掉它。要更硬的约束需要用 Chrome 托管策略强制安装（`ExtensionSettings` + `installation_mode: force_installed`），那是另一套东西。
- 只管 Chrome。手机 App、Safari、其他浏览器都不受影响。
- 恢复的是原网页地址；浏览器后退可能保留滚动位置等状态，但未提交输入、动态页面状态无法保证恢复。旧屏蔽页如果没有可用的后退历史，也无法推断原网址。
- Chrome 的 alarm 可能延迟，休眠期间不会唤醒电脑，因此结束时间是自动恢复的目标时间，并非严格实时保证。
- `host_permissions` 用了 `http://*/*` 和 `https://*/*`，因为 DNR 的 redirect 动作需要目标站点的主机权限，而屏蔽名单是可配置的、不能写死在 manifest 里。
